## Cierre de esta continuación

- **Mi operador:** en Edge, con una cuenta sintética autorizada y PostgreSQL efímero, se guardó un nombre, se detuvo la API y el POST mostró el error conservando el valor. Tras restaurar la misma API, se reintentó sin volver a escribir el nombre y la recarga confirmó la persistencia.
- **Estados de Backoffice:** Acceso denegado, API no disponible y Error se revisaron visualmente en rutas directas, a 1440×1000 y 390×844 CSS px. En las seis vistas `scrollWidth` coincidió con `innerWidth`. Esta revisión no simula denegación real, caída funcional de la API ni una excepción.
- **Tracking:** el endpoint público con fixture sintético vigente devolvió HTTP 200, estado `AsignadoRuta` e identidad del operador. La captura no muestra la ruta del token; no se hicieron envíos de comunicación.
- **Assets anteriores:** la captura de ruta citada por la tabla heredada no está en el checkout; su resultado textual se conserva, sin presentarla como imagen disponible.
- **Zoom nativo:** cinco atajos Ctrl+Plus enviados a Edge headless no alteraron `devicePixelRatio` ni el viewport CSS. Eso no demuestra 200 % de zoom nativo; queda pendiente una comprobación manual en navegador con interfaz.
- **RDD:** estado local confirmado por CLI: `global=on`, `clone_local=off`, `effective=off`. La revisión nativa anterior permanece interrumpida y sin aprobación. No se cambió el modo.
- No se modificó código de producto ni se repitieron suites/builds válidos. El fixture de reglas/envío/token existió solo en la base PostgreSQL efímera; no se modificaron bases persistentes, Compose ni se enviaron comunicaciones reales.

## Actualización — búsqueda y detalle de Envíos recibidos (2026-10-22)

### Causa y corrección

- **Causa reproducida:** la solicitud real del formulario con `Buscar=01a1649c-352e-78dc-ab28-aa0d23a830dc`, `Estado=` y `Pagina=1` llega al model binder de ASP.NET Core con `Estado` en `null`. `OnGetAsync` ejecutaba `Estado.Trim()` y lanzaba `NullReferenceException` antes de consultar `api/envios`. La regresión `ReceivedShipmentsSearchAcceptsAnExplicitlyEmptyStateFilter` falló primero con HTTP 500 y el stack señaló `IndexModel.OnGetAsync`, línea 77.
- **Corrección:** búsqueda y estado se normalizan como cadenas vacías cuando el binder recibe null; estados desconocidos se normalizan a “Todos los estados”; página inválida se ajusta a 1 y páginas fuera de rango se limitan al total. La búsqueda local sigue operando exclusivamente sobre la lista completa que devuelve el endpoint autorizado existente. El predicado tolera también nombres opcionales ausentes en una respuesta individual; los errores de API conservan filtros y muestran reintento, sin convertirse en lista vacía.
- **Contrato:** no se modificó API, esquema, permisos ni cliente HTTP. UUID, comercio y destinatario se buscan localmente junto al filtro de estado porque el contrato actual entrega el conjunto completo autorizado.

### Detalle lateral

- Se reemplazó el popover por un diálogo Offcanvas de Bootstrap existente, limitado a 620 px en escritorio y al ancho disponible en móvil. El diálogo se alimenta de los datos ya cargados por la lista y no genera una consulta redundante.
- Conserva encabezado, filtros, tabla y tarjetas móviles. Presenta UUID abreviado y copia completa, estado textual/semántico, destinatario/dirección, comercio/operador, número de bultos, peso total calculado solo de pesos presentes y datos por bulto con unidades. Los campos técnicos están cerrados inicialmente; cancelación conserva la autorización y confirmación existentes.
- Bootstrap aporta backdrop, `aria-modal`, trampa de foco, Escape y bloqueo/restauración del scroll. El foco inicial va al título; al cerrar vuelve al botón “Ver detalle” que abrió el envío. El fondo del portal queda inerte durante la apertura. `prefers-reduced-motion` se respeta.
